# Riskfate — основа планування

Цей документ фіксує **рекомендації для обговорення**, а не остаточно затверджені технічні стандарти. Мета — розвивати гру маленькими частинами, але так, щоб зміна одного компонента не вимагала переробки багатьох інших.

## Три рівні планування

### 1. Бачення всієї гри — загально
Визначити принципи майбутньої MMORPG: ігровий світ, атмосферу, основний ігровий процес, взаємодію гравців, складність і розвиток персонажа. Поки без детального опису кожної механіки та локації.

### 2. Технічні стандарти — уважно
Перед створенням залежних компонентів погодити спільні правила: масштаб графіки, координати, організацію файлів і ресурсів, принципи мережевої архітектури та взаємодії систем. Не будувати складних систем наперед.

### 3. Детальна реалізація — поступово
Створювати й перевіряти окремі невеликі частини: стартовий екран, мінімальний інтерфейс, персонажа, початкову локацію та перші взаємодії. До наступного кроку переходити після перевірки попереднього.

## Що важливо продумати заздалегідь

| Напрямок | Питання для погодження |
| --- | --- |
| **Графіка** | Стиль, пропорції персонажів, масштаб світу |
| **Роздільність** | Базовий viewport, масштабування, різні екрани |
| **Карти** | Система тайлів, координати, організація локацій |
| **Структура** | Розміщення сцен, скриптів і ресурсів |
| **Мережа** | Розподіл відповідальності між клієнтом і сервером |
| **Інтерфейс** | Принципи компонування та масштабування |
| **Дані** | Опис персонажів, предметів та інших ігрових сутностей |
| **Світ** | Загальна географія, атмосфера, основи лору |

**Важливо:** цей перелік — список тем, які потрібно обдумати, а не вимога зараз усе реалізовувати. Конкретні значення (наприклад, розміри тайлів чи структура папок) ще **не затверджено**.

## Правило прийняття рішень

Спочатку обговорюємо й оцінюємо альтернативи, потім користувач затверджує рішення. Без його дозволу нічого в проєкті не змінюється.
