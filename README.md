# Riskfate

**Riskfate** — проєкт безплатної фентезійної MMORPG, яку планується поступово розробляти на **Godot**. У центрі задуму — небезпечний світ, свобода розвитку персонажа, майстерність зброї, матеріальні навики та довгостроковий прогрес.

Проєкт має працездатний технічний Web-прототип для перевірки героя, масштабу й керування. Концепція та архітектура майбутньої MMORPG продовжують уточнюватися; остаточні технічні параметри та склад першої ігрової версії ще не затверджені. Сервер, мережеву синхронізацію, бойові та інші ігрові системи не реалізовано.

## Браузерний тест спрайтів — RF-DEV-001

[Відкрити Riskfate у браузері](https://levian47.github.io/riskfate/).

Проєкт розташований у корені: [project.godot](project.godot). Головна сцена — [scenes/hero_web_test.tscn](scenes/hero_web_test.tscn), її скрипт зберігається поруч: [hero_web_test.gd](scenes/hero_web_test.gd).

Це технічний прототип: герой, сітка 32×32, вісім статичних ракурсів і масштаби ×1/×2/×4/×8. Розміри, швидкість і параметри показу залишаються **тестовими до окремого рішення власника**.

- **Рух:** WASD/стрілки на ПК; на сенсорному екрані — аналоговий джойстик. Напрямок руху довільний, швидкість залежить від відхилення пальця, а ракурс обирається з найближчих восьми напрямків. Діагональна швидкість нормалізована; після зупинки ракурс зберігається.
- **Ракурс на місці:** кнопка «Ракурс» проходить S, SE, E, NE, N, NW, W, SW.
- **Масштаб:** кнопки ×1/×2/×4/×8 змінюють лише цілочисельний zoom камери. Сітка масштабується разом із героєм.
- **Телефон:** підтримано вертикальне та горизонтальне компонування. Джойстик відображається лише за наявності сенсорного екрана, розташований поза ігровою областю й замінює вісім старих кнопок руху. Лише UI масштабується за щільністю дисплея. Відпускання/скасування дотику, зміна розміру вікна та втрата фокуса зупиняють джойстик. За недостатнього місця великий кадр обрізається краями області з відповідним повідомленням; автоматичного зменшення чи дробового zoom немає.
- **Чіткість:** Nearest, без mipmaps, точка опори (24, 62), цілі координати. Ігрова область — SubViewport, розмір якого дорівнює розміру його контейнера; stretch контейнера й вікна вимкнено. Джерельний PNG не ресемплюється.
- **Текстура:** `characters/player/base_hero/hero_8dir.png` — побайтова копія затвердженого атласу 384×64. `assets_source/` виключено з імпорту; контрольний аркуш не використовується.

### Перевірки та підтвердження власника

Для коду [6814baf93e8d35c4cb5055ba26a72d4c150742d0](https://github.com/levian47/riskfate/commit/6814baf93e8d35c4cb5055ba26a72d4c150742d0) [GitHub Actions від 04.11.2026](https://github.com/levian47/riskfate/actions/runs/41905035668) успішно виконав імпорт, 169 перевірок Godot, запуск сцени, Web-експорт, публікацію Pages та перевірки Chrome до й після публікації. Перевірено показ джойстика за наявності сенсорного екрана, приховування без нього, зіставлення восьми ракурсів із PNG, довільні напрямки руху, відпускання/скасування дотику, поворот екрана, втрату фокуса та розміри вікна з DPR 1/2.

**Підтвердження власника від 04.11.2026:** графічний тест у вебверсії Godot на смартфоні успішний, герой чіткий на перевірених масштабах. Після перевірки джойстика власник окремо повідомив: «Тест пройдено, сенсорний джойстик працює». Модель пристрою, версії ОС/браузера й повна матриця перевірених на ньому сценаріїв не зафіксовані. Ці підтвердження не затверджують остаточний масштаб світу чи сумісність з усіма смартфонами.

### Локальний запуск

Потрібні **Godot 4.7.2 Stable Standard** і відповідні **4.7.2.stable export templates**. Compatibility Renderer, GDScript.

```sh
godot --version
godot --headless --path . --import
godot --path .
# Автоматичні перевірки сцени:
godot --headless --path . --script res://scenes/hero_web_test_check.gd
# Експорт:
mkdir -p dist
godot --headless --path . --export-release Web dist/index.html
# Відкрити http://localhost:8000 після запуску:
python3 -m http.server 8000 --directory dist
```

### GitHub Actions і Pages

[Workflow](.github/workflows/godot-web.yml) збирає `main` офіційним Web Export: **без потоків**, без GDExtension, без PWA/service worker і без вимоги COOP/COEP. Версії рушія й templates зафіксовані як **4.7.2**, архіви перевіряються SHA-256. У Web-пакет входить лише головна сцена з її залежностями; `dist/` не комітиться.

Публікація використовує офіційні `upload-pages-artifact` / `deploy-pages`; окремої гілки `gh-pages` немає. Якщо Pages вимкнено: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Потім **Actions → Build and deploy Riskfate Web test → Run workflow** або **Re-run failed jobs** для невдалого розгортання. Якщо середовище `github-pages` запитує ручне схвалення, його надає власник у GitHub.

Тести сцени містяться в [hero_web_test_check.gd](scenes/hero_web_test_check.gd), браузерні перевірки — у [check-web.mjs](.github/scripts/check-web.mjs). CI перевіряє побайтову копію атласу, відповідність восьми кадрів оригіналам, вибір найближчого ракурсу, нормалізацію клавіатурного й пропорційну швидкість аналогового руху, утримання/відпускання/скасування дотиків, втрату фокуса та компонування. Перед публікацією перевіряє Web-збірку в Chrome через локальний HTTP-сервер CI; після публікації повторно перевіряє HTTPS і вміст HTML/JS/WASM/PCK та запускає Chrome з імітацією мобільних розмірів і дотиків. Скріншоти доступні в артефактах `riskfate-browser-check` і `riskfate-published-browser-check`. Перевірка браузера використовує встановлені на runner Chrome та Node.js без npm-пакетів; це лише інструменти CI.

Workflow автоматично запускається для змін у файлах проєкту, експортному preset, сценах, `characters/`, самому workflow та `.github/scripts/`; також доступний ручний `workflow_dispatch`. Коміт лише Markdown-документації не запускає Web-збірку за поточним фільтром `paths`. `dist/` створюється під час експорту та відсутній у вихідному дереві Git.

**Межі перевірки:** Chrome з імітацією телефона не є Android Chrome на фізичному пристрої. Для наступних змін клієнта потрібна відповідна повторна перевірка на телефоні; підтвердження власника вище стосується вже виконаного тесту, а не майбутніх версій. Браузерний zoom/системне масштабування пристрою також можуть впливати на фактичний показ; оцінювати при початковому масштабі сторінки. Успішна збірка не затверджує ігрових параметрів і не доводить повної мобільної сумісності.
